Usei o Claude Code com o modelo Opus 5.5 que em sua maioria, no terminal, e a extensão do claude no chrome, para o code conseguir deburar o navegador e navegar pela UI.

Antes de já começar a codagem do projeto, escrevi com o claude arquivos spec .md para o planejamento do projeto. Neles registrei as decisões de arquitetura, modelagem de domínio, regras de negócios, e a divisão do trabalho em 10 fases, esse plano foi como um roteiro pro claude, cada fase só começava após a anterior está concluida e revisada por mim.

Nesse plano, foi especificado o scaffolding e implementação do backend e frontend, os testes de integração usando o Testcontainers, de concorrência e de arquitetura com o ArchUnit, as documentações e ADRs, a infra compondo a pipeline e script de deploy, e a validação do projeto usando a UI do projeto pela deburação do navegador.

A IA erra um pouco principalmente nessa etapa inicial, onde se não for especificado muito bem o que é necessário para o projeto, ela começa a escrever no plano um projeto muito maior do que o necessário, nesse caso ela começou a crescer algumas camadas e inserir outras features, como uma parte específica para o crud de usuario e alteração do seu perfil de acesso, notei que começou a ficar muito grande e fui diminuindo.

Outro ponto que a IA nesse caso foi um pouco falha, foi na questão visual do frontend, por exemplo, o espaçamento dos campos de escrita, estavam muito colados um no outro, mesmo o claude acessando o navegador ele não pegou esses erros de UI, tendo que eu solicitar explicitamente para ele adicionar um margin bottom nos campos de escrita, outro exemplo é a questão da exibição de mensagem, como por exemplo o dado de Data, ele não teve essa noção de que exibir "2026-02" para o usuário não é a melhor forma de exibir data, pois principalmente por estar no idioma brasileiro ter o formato de dd/MM/yyyy, então solicitei para ele identificar o problema passando o response da request e ele encontrou o problema e corrigiu para exibir a data formatada para o usuario 

Em relação a escrita manual de código, eu não escrevi manualmente praticamente nada do código, prefiro estar direcionando, decidindo e revisando as alterações com o claude, por alguns motivos, um deles é a manutenção do contexto, quando existe ações manuais no código, a IA se perde nas modificações e começa a interpretar aquele código de forma separada do resto por não der sido ela que fez, outro motivo é, por exemplo, o erro de exibição de data, o claude pode identificar onde está o problema e propor uma solução mais adequada pra aquele caso se houver mais de uma incidência, ou seja, nesses casos direcionados ele consegue olhar várias partes do projeto de forma mais eficiente que uma pessoa, e propor uma solução mais eficiente, então acredito que solicitar para a ia realizar essa correção é melhor do que ir la e fazer manualmente, mas em contrapartida, é necessário informar mais detalhes para a ia conseguir identificar erros, mandando logs, prints, o fluxo que surgiu o erro, para ela ser mais acertiva. Tirando a escrita de código, tive que algumas ações manuais, como a configuração da VM, da cloudflare, das env no github para o deploy público, além das decisões do projeto e escopo.

Para a validação dos códigos feita pela IA, sempre que ela realiza alguma alteração eu reviso as alterações feitas com diff, essa parte é muito necessária principalmente quando envolve arquivos que são usados por diversos lugares e onde tem métodos sensíveis, faço também execuções manuais para verificar se as ações básicas foram afetadas, e uma peça muito importante para essa validação é os teste automatizados com ci, principalmente para ver se algo quebrou no projeto.
